# Export / import package format (Google CX Agent Studio, "CES")

Sources: the official page "Export and import" and the export format reference
(`docs.cloud.google.com/gemini-enterprise-cx/cx-agent-studio/reference/export.md.txt`), the REST reference for
App, Agent, Tool, Toolset and Guardrail, and **three real console exports** of a Salesforce voice agent: the first with a Python tool only,
the second with the Salesforce connector (OpenAPI toolset with OAuth), an `environment.json` and the model changed to `gemini-composite-v2`,
the third with a transcript-saving tool, an after-model callback, a PATCH-by-external-id connector operation and sequential tool execution.
`scripts/compare_to_export.py <built package> <export>` repeats the comparison for any new export.

## Trust levels used in this skill

| Level | Meaning |
|---|---|
| VERIFIED | Present in a real console export, and `build_agent.py` reproduces its keys exactly (structural diff in the skill's test run). The Python-tool-plus-connector design was also run end to end in the console, and so was the transcript saver (Preview simulator, row saved in Salesforce) |
| DOCUMENTED | In Google's docs, never seen in a real export by this skill. Built from the docs. |
| UNVERIFIED | A reasonable inference. Always tell the user, and suggest the smoke import first. |

## Package layout

A zip whose single top-level folder is the app name with spaces replaced by `_`. JSON or YAML files are both accepted on
import; this skill writes JSON like the console does. All references between objects use `displayName`, never file names.

```
Pharma_Order_Assistant/
  app.json                                   VERIFIED
  global_instruction.txt                     DOCUMENTED  (app.json "globalInstruction": "global_instruction.txt")
  pythonEnvFiles/pythonEnvFiles.json         VERIFIED    (the console always writes it, content "{ }")
  agents/<Agent_name>/<Agent_name>.json      VERIFIED
  agents/<Agent_name>/instruction.txt        VERIFIED
  agents/<Agent_name>/<type>_callbacks/<type>_callbacks_NN/python_code.py   VERIFIED for after_model (NN = 01, 02, ... in order); the other five types
                                             are assumed to follow the same pattern. The template name is NOT in the path: tell callbacks apart by their code
  tools/<tool_name>/<tool_name>.json         VERIFIED (pythonFunction tools)
  tools/<tool_name>/python_function/python_code.py   VERIFIED
  environment.json                           VERIFIED    (real values for every $env_var placeholder; written whenever toolsets exist)
  toolsets/<name>/<name>.json                VERIFIED    (openApiToolset with oauthConfig; placeholders for secret version and token endpoint)
  toolsets/<name>/open_api_toolset/open_api_schema.yaml   VERIFIED (YAML; servers[0].url is "$env_var")
  guardrails/<Guardrail_name>/<Guardrail_name>.json   VERIFIED for modelSafety and llmPromptSecurity; DOCUMENTED for the rest
  guardrails/<name>/guardrail_callback/python_code.py   UNVERIFIED path
  examples/ evaluations/ evaluationDatasets/ environment.json     not generated by this skill
```

Folder names: displayName with every run of characters outside `A-Za-z0-9_-` replaced by `_` ("Root agent" -> `Root_agent`).

## app.json (VERIFIED keys)

```json
{
  "name": "<uuid>",
  "displayName": "Pharma Order Assistant",
  "rootAgent": "Root agent",                       // displayName of the entry agent
  "audioProcessingConfig": {                       // voice apps only
    "synthesizeSpeechConfigs": {"en-US": {"voice": "en-US-Chirp3-HD-Rasalgethi", "speakingRate": 1.0}},
    "bargeInConfig": {"bargeInAwareness": true},
    "inactivityTimeout": "10s",
    "ambientSoundConfig": {"prebuiltAmbientSound": "office_3"}
  },
  "loggingSettings": {"redactionConfig": {"enableRedaction": true},        // only when redaction is on
                      "audioRecordingConfig": {}, "bigqueryExportSettings": {}, "cloudLoggingSettings": {},
                      "conversationLoggingSettings": {"retentionWindow": "31536000s"},
                      "metricAnalysisSettings": {}, "unredactedBigqueryExportSettings": {}},   // the console writes every block, unused ones empty
  "guardrails": ["Default Safety Guardrail", "Default Prompt Guardrail"],   // displayNames applied app-wide
  "modelSettings": {"model": "gemini-3.5-flash", "thinkingLevel": "MEDIUM"},
  "variableDeclarations": [{"name": "x", "description": "...", "schema": {"type": "STRING", "default": ""}}],
  "defaultChannelProfile": {"personaProperty": {"persona": "CHATTY"}, "disableDtmf": false, "disableBargeInControl": false},
  "timeZoneSettings": {"timeZone": "America/Los_Angeles"},
  "toolExecutionMode": "SEQUENTIAL",               // only when set; absent means PARALLEL (VERIFIED key and value)
  "errorHandlingSettings": {"errorHandlingStrategy": "FALLBACK_RESPONSE", "fallbackResponseConfig": {"maxFallbackAttempts": 1}, "endSessionConfig": {"escalateSession": true}}
}
```
Notes
- The console omits keys whose value is the proto default (`false`, `0`, `""`). A guardrail with no `"enabled"` key is therefore **disabled**.
  The real export's *Default Prompt Guardrail* had no `enabled` key: prompt-injection protection was off. This skill writes `enabled: true`.
- `variableDeclarations[].description` is "required" in the REST reference but the console writes variables without one (and a STRING variable with no default); this skill writes a description anyway.
- Composite voice models (`gemini-composite-v2`) are exported as `"modelSettings": {"model": "gemini-composite-v2"}` with **no** `thinkingLevel`. Text models carry `thinkingLevel`.
- Turning redaction on adds `"redactionConfig": {"enableRedaction": true}`; every other logging block is written as an empty object whether used or not.
- `variableDeclarations[].schema.type`: STRING, NUMBER, INTEGER, BOOLEAN, OBJECT, ARRAY. The default value lives inside `schema`.
- Other documented keys: `description`, `languageSettings {defaultLanguageCode, supportedLanguageCodes, enableMultilingualSupport}`,
  `globalInstruction`, `cloudLoggingSettings`,
  `bigqueryExportSettings`, `audioRecordingConfig {gcsBucket}`, `environment.json`.
- **Never write secrets here.** Variable defaults are plain text in the export. A real export contained a live Salesforce access token.

## Agent json

```json
{"name": "<uuid>", "displayName": "Root agent", "description": "...",
 "instruction": "agents/Root_agent/instruction.txt",
 "tools": ["authenticate_user", "end_session"],              // VERIFIED. System tools are listed by name.
 "toolsets": [{"toolset": "salesforce_connector", "toolIds": ["get_case_by_id"]}],   // DOCUMENTED
 "childAgents": ["billing_agent"],                           // DOCUMENTED: parent -> child only, one parent each, root is never a child
 "afterModelCallbacks": [{"pythonCode": "agents/Root_agent/after_model_callbacks/after_model_callbacks_01/python_code.py"}],   // VERIFIED: only pythonCode
 "guardrails": ["Extra Guardrail"], "modelSettings": {"model": "..."}}
```
Callback keys: `before/afterAgentCallbacks`, `before/afterModelCallbacks`, `before/afterToolCallbacks`. The console wrote no `disabled` or `description`
for a default callback (the REST reference lists both as optional fields, so they are accepted when set, but only `pythonCode` has been seen in an export).
A connector operation that is not attached to the agent can still be called from a Python tool; the agent json then lists only the Python tools.
System tool names are reserved: `end_session`, `transfer_to_agent`, `customize_response` (never use them for your own tools).

## Python tool json (VERIFIED)

```json
{"name": "<uuid>",
 "pythonFunction": {"name": "authenticate_user", "pythonCode": "tools/authenticate_user/python_function/python_code.py",
                    "description": "<the docstring, cleaned>"},
 "executionType": "SYNCHRONOUS", "displayName": "authenticate_user"}
```
`pythonFunction.name` must equal the function defined in the code and the tool name (snake_case). Other tool kinds the REST reference lists
(openApiTool, googleSearchTool, connectorTool, dataStoreTool, fileSearchTool, mcpTool, widgetTool, clientFunction, agentTool, remoteAgentTool)
are not generated by this skill; add them in the console after import.

## Toolset json (VERIFIED against a real export with OAuth)

```json
{"name": "<uuid>", "displayName": "query_salesforce",
 "openApiToolset": {"openApiSchema": "toolsets/query_salesforce/open_api_toolset/open_api_schema.yaml",
                    "apiAuthentication": {"oauthConfig": {"oauthGrantType": "CLIENT_CREDENTIAL", "clientId": "<consumer key>",
                                                          "clientSecretVersion": "$env_var", "tokenEndpoint": "$env_var"}}},
 "description": "..."}
```
`environment.json` (root) carries the real values, keyed by toolset name:
```json
{"toolsets": {"query_salesforce": {"openApiToolset": {
   "apiAuthentication": {"oauthConfig": {"clientSecretVersion": "projects/<project>/secrets/<secret>/versions/1",
                                         "tokenEndpoint": "https://<domain>.my.salesforce.com/services/oauth2/token"}},
   "url": "https://<domain>.my.salesforce.com/services/data/v68.0"}}}}
```
No `scopes` key: for Salesforce leave scopes empty (a scope in the request gives `scope parameter not supported`). Keys equal to a default (`executionType: SYNCHRONOUS`, `ignoreUnknownFields: false`) are omitted by the console.
The consumer key (`clientId`) is not secret but identifies your app; the secret itself lives only in Secret Manager. The schema file is YAML in the real export (JSON is also accepted on import).
`apiAuthentication` holds exactly one of: `bearerTokenConfig {token: "$context.variables.<name>"}`,
`oauthConfig {oauthGrantType: CLIENT_CREDENTIAL, clientId, clientSecretVersion: "projects/P/secrets/S/versions/V", tokenEndpoint, scopes[]}`
(client credentials is the **only** supported OAuth grant), `apiKeyConfig`, `serviceAccountAuthConfig`, `serviceAgentIdTokenAuthConfig`.
The server URL is taken from `servers[0].url` of the schema. On export Google moves URLs/secret names into `environment.json` as `$env_var`.

## Guardrail json (see guardrails-guide.md)

Exactly one type key (`contentFilter`, `llmPromptSecurity`, `llmPolicy`, `modelSafety`, `codeCallback`, `supervisor`) and one action key
(`respondImmediately {responses:[{text}]}`, `transferAgent {agent}`, `generativeAnswer {prompt?}`).

## Rules the validator enforces (validate_package.py)

Structure and references exist; displayNames unique; python code compiles and defines the named function; tool params typed and documented;
`{@TOOL: x}` / `{@AGENT: x}` / variables resolve; XML tags balanced and every `<step>` has trigger and action; `end_session(` / `customize_response(`
used only when listed in `tools`; guardrail enums valid; bearer token variable exists; **no secrets anywhere** (Salesforce session ids, Bearer tokens,
private keys, API keys, assigned `secret = "..."`, secret-looking variable names with defaults).
